# Creating the SourceGit macOS Application Bundle

These instructions are specific to **macOS** and describe how to publish SourceGit as a self-contained application for Apple Silicon Macs, create the `.app` bundle, configure `Info.plist`, copy the published files, and remove macOS quarantine attributes.

> Note: the commands below use the `osx-arm64` runtime and are intended for Macs with Apple Silicon processors, such as M1, M2, M3, or M4.

## Prerequisites

- macOS.
- The .NET SDK installed.
- A local clone of the SourceGit repository.
- A terminal opened in the repository's root directory.
- Administrator privileges to write to `/Applications` and use `sudo`.

Verify that the project file exists:

```sh
ls src/SourceGit.csproj
```

## 1. Publish as self-contained

Publish SourceGit in `Release` mode for macOS on Apple Silicon. The `--self-contained` option includes the .NET runtime in the output, so the .NET runtime does not need to be installed separately on the target machine.

```sh
dotnet publish src/SourceGit.csproj -c Release -r osx-arm64 --self-contained
```

The output will be generated in:

```text
src/bin/Release/net10.0/osx-arm64/publish/
```

If the project uses a different .NET version, the `net10.0` segment of the path may be different.

## 2. Create the `.app` bundle structure

Create the standard directories for a macOS application bundle:

```sh
mkdir -p /Applications/SourceGit.app/Contents/MacOS
mkdir -p /Applications/SourceGit.app/Contents/Resources
```

The initial structure will be:

```text
/Applications/SourceGit.app/
└── Contents/
    ├── MacOS/
    └── Resources/
```

## 3. Create the `Info.plist` file

The `Info.plist` file contains the main metadata for the macOS application:

```sh
cat > /Applications/SourceGit.app/Contents/Info.plist << 'EOF'
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
    <key>CFBundleName</key>
    <string>SourceGit</string>
    <key>CFBundleDisplayName</key>
    <string>SourceGit</string>
    <key>CFBundleIdentifier</key>
    <string>com.yourname.sourcegit</string>
    <key>CFBundleVersion</key>
    <string>1.0.0</string>
    <key>CFBundleShortVersionString</key>
    <string>1.0.0</string>
    <key>CFBundleExecutable</key>
    <string>SourceGit</string>
    <key>CFBundlePackageType</key>
    <string>APPL</string>
    <key>NSHighResolutionCapable</key>
    <true/>
</dict>
</plist>
EOF
```

Replace `com.yourname.sourcegit` with an appropriate unique identifier if necessary. For example:

```text
com.example.sourcegit
```

## 4. Copy the published files into the bundle

Copy all files generated by `dotnet publish` into the bundle's `Contents/MacOS` directory:

```sh
cp -a src/bin/Release/net10.0/osx-arm64/publish/* /Applications/SourceGit.app/Contents/MacOS/
```

After the copy operation, the bundle will contain the main executable and its dependencies in the `Contents/MacOS` directory.

## 5. Make the main executable executable

Set the execute permission on the SourceGit executable:

```sh
chmod +x /Applications/SourceGit.app/Contents/MacOS/SourceGit
```

## 6. Remove quarantine attributes

If the application was downloaded or copied from an external source, macOS may apply quarantine attributes. The following command recursively removes those attributes from the bundle:

```sh
sudo xattr -cr /Applications/SourceGit.app
```

Enter your macOS account password when prompted.

> Warning: `xattr -cr` modifies the extended attributes of the application. Use it only with software whose origin you know and trust. Removing quarantine attributes does not replace application signing or notarization.

## 7. Launch SourceGit

After completing all the steps, launch the application with:

```sh
open /Applications/SourceGit.app
```

Alternatively, open the `/Applications` folder in Finder and double-click `SourceGit.app`.

## Complete command sequence

Run these commands from the SourceGit repository's root directory:

```sh
dotnet publish src/SourceGit.csproj -c Release -r osx-arm64 --self-contained

mkdir -p /Applications/SourceGit.app/Contents/MacOS
mkdir -p /Applications/SourceGit.app/Contents/Resources

cat > /Applications/SourceGit.app/Contents/Info.plist << 'EOF'
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
    <key>CFBundleName</key>
    <string>SourceGit</string>
    <key>CFBundleDisplayName</key>
    <string>SourceGit</string>
    <key>CFBundleIdentifier</key>
    <string>com.yourname.sourcegit</string>
    <key>CFBundleVersion</key>
    <string>1.0.0</string>
    <key>CFBundleShortVersionString</key>
    <string>1.0.0</string>
    <key>CFBundleExecutable</key>
    <string>SourceGit</string>
    <key>CFBundlePackageType</key>
    <string>APPL</string>
    <key>NSHighResolutionCapable</key>
    <true/>
</dict>
</plist>
EOF

cp -a src/bin/Release/net10.0/osx-arm64/publish/* /Applications/SourceGit.app/Contents/MacOS/
chmod +x /Applications/SourceGit.app/Contents/MacOS/SourceGit
sudo xattr -cr /Applications/SourceGit.app
open /Applications/SourceGit.app
```

## Final verification

Check that the bundle has the expected structure:

```sh
find /Applications/SourceGit.app -maxdepth 3 -print
```

Verify that `Info.plist` is valid:

```sh
plutil -lint /Applications/SourceGit.app/Contents/Info.plist
```

Check the type of the main executable:

```sh
file /Applications/SourceGit.app/Contents/MacOS/SourceGit
```

On an Apple Silicon Mac, the output should indicate an `arm64` binary or a binary compatible with Apple Silicon.
